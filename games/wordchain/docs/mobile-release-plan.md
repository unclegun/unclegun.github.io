# WordChain mobile release plan

Status: **web/PWA foundation only.** No native project exists. A PWA does not by itself guarantee acceptance by Apple or Google.

## 1. Readiness levels
| Level | Meaning | State |
|---|---|---|
| Web | Playable on GitHub Pages, mobile browsers | Yes |
| PWA | Manifest, icons, service worker, offline cache | Added in 2.1; offline restart still needs real-browser verification |
| Native-store | Signed binaries, store listings, review passed | Not started |

## 2. Approach: Capacitor
Recommended: wrap the static site with [Capacitor](https://capacitorjs.com). It keeps the vanilla JS/ES-module code unchanged, bundles assets inside the app (true offline, no service-worker dependency) and gives access to status bar, safe area, haptics and lifecycle plugins. Alternatives (Trusted Web Activity for Android only, Cordova, native rewrite) are less suitable: TWA does not cover iOS; a rewrite throws away working code.

Introduce Capacitor only after the PWA is verified on devices. Expected structure:
```
games/wordchain/            # web source (webDir)
capacitor.config.ts         # appId, appName, webDir: "games/wordchain"
android/                    # generated by `npx cap add android`
ios/                        # generated by `npx cap add ios` (needs macOS + Xcode)
```
Word lists are bundled in `data/`, so offline bundling needs no change; load them via relative URLs (already the case). Under `capacitor://` / `https://localhost` origins `fetch` of bundled files works; confirm in a device test.

## 3. Native considerations
- **Lifecycle:** save on `visibilitychange`/`pagehide` (and Capacitor `appStateChange`). Anarchy audio already suspends when hidden; confirm resume on foreground.
- **Save migration:** keys are `wordchain.v2.*` plus `wordchain.anarchy.*`. WebView storage can be cleared by the OS under pressure; consider mirroring to Capacitor Preferences. Keep `validateSave` as the gate for outdated/malformed data.
- **Audio:** iOS requires a user gesture to start Web Audio; music is already opt-in via a click. Test silent switch behavior and interruptions (calls).
- **Safe areas/status bar:** `viewport-fit=cover` is set; use `env(safe-area-inset-*)` padding and the Status Bar plugin for style.
- **Orientation:** portrait-first (manifest says `portrait-primary`); decide whether tablets/foldables may rotate and test the crossword at both sizes.
- **Updates:** the service worker waits instead of skipping waiting so active games are not swapped mid-run; in native, versions ship via the store.

## 4. Store assets
- Icon: 1024×1024 PNG without transparency (iOS); 512×512 PNG plus adaptive icon (Android). Source art: `icons/icon.svg`.
- Screenshots: iOS 6.9" and 6.5" iPhone sets (and iPad if supported); Android phone 16:9/9:16 min 2 screenshots, feature graphic 1024×500.
- Listing text, category (Games › Word), age rating questionnaire.

## 5. Privacy and data inventory
The game uses no backend, accounts, analytics or ads. Data stored locally only: run saves, best scores, tutorial flags, audio preferences, local playtest counters (never uploaded). Apple "App Privacy" answer: Data Not Collected; Google Data safety: no data collected or shared. Re-verify before submission and publish a privacy policy URL.

## 6. Accessibility checks
VoiceOver/TalkBack walkthrough of guessing, shop and every event; Dynamic Type/large font; contrast across all nine Anarchy palettes; reduced motion; touch targets ≥44pt; no color-only feedback.

## 7. Review risks
Apple 4.2 (minimum functionality) is the main risk for web wrappers: ship native touches (haptics, offline, proper icons, share sheet) and a polished experience. Google requires target API level compliance and a Data safety form. Do not claim features (offline, accessibility) in listings until verified.

## 8. Testing, signing, release
- Devices: at least one small and one large iPhone, a mid-range Android, a tablet/foldable, offline and low-memory cases.
- Android: upload keystore, Play App Signing, internal → closed → production tracks, AAB.
- iOS: Apple Developer account, certificates/profiles, TestFlight, then App Store Connect review.
- Versioning: semantic `MAJOR.MINOR.PATCH` for the web (`sw.js` VERSION), monotonically increasing build number for stores; tag releases in git; keep a changelog and keep save migration tests for each shipped version.
